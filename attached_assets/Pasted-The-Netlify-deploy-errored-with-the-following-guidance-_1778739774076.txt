The Netlify deploy errored, with the following guidance provided:

Diagnosis
- The build runs the workspace website build: [line 82](#L82) and invokes Vite: [lines 84–85](#L84-L85).
- Vite fails to load the config because the config file requires a PORT env var and throws: [line 86](#L86) and the thrown message at [line 88](#L88) shows "Error: PORT environment variable is required but was not provided."
- Because the config throws during load, the build exits with status 1: [line 99](#L99) and Netlify reports the build failed: [line 120](#L120).

Cause
- vite.config.ts expects PORT to be defined at config-load time and throws an error when it is missing. That prevents Vite from loading the configuration and aborts the build.

Solution
You have two practical fixes. Pick one or apply both.

Option A — (Quick) Set PORT in Netlify environment variables
1. In the Netlify site settings go to Site settings → Build & deploy → Environment → Environment variables.
2. Add an environment variable named PORT with a value (e.g. 3000 or 5173).
3. Redeploy.

This supplies PORT during build so vite.config.ts will not throw. (No code changes required.)

Option B — (Recommended) Make vite.config.ts tolerant when PORT is missing
1. Open artifacts/website/vite.config.ts in the repo:
   https://github.com/FarhanHossen/VORTREXYN-Bubble-Pop/blob/main/artifacts/website/vite.config.ts
2. Replace the code that throws when PORT is absent with a safe default or only require PORT during dev. Example change:

```ts
// artifacts/website/vite.config.ts
import { defineConfig } from 'vite';

// Safe default: prefer process.env.PORT, then VITE_PORT, then fallback
const PORT = process.env.PORT ?? process.env.VITE_PORT ?? '5173';

export default defineConfig(({ command }) => {
  // If you only need PORT during serve (dev), you can conditionally use it:
  const serverConfig = command === 'serve' ? { port: Number(PORT) } : undefined;

  return {
    server: serverConfig,
    // ...other config
  };
});
```

Or, if you want to keep a check only for local development:

```ts
if (process.env.NODE_ENV === 'development' && !process.env.PORT) {
  throw new Error('PORT environment variable is required for development.');
}
```

3. Commit and push the change, then trigger a new Netlify deploy.

Notes
- Option B is preferred because it avoids failing builds when Netlify (or CI) doesn't provide PORT for a static build.
- If you choose Option A, verify that the environment variable was set in the Netlify UI before redeploying.
